# 动作/割草类分析模板 — Module C: 交互与系统

> 适用于：Vampire Survivors 类、Musou 类、横向/纵向割草、任何"大量敌人涌来、玩家以攻击/闪避应对"的动作游戏

## 使用说明

本模板是动作/割草类分析的第 3 个模块（共 4 个）。执行顺序：A → B → C → D。

**前置依赖**：Module A 的实体 ID 清单 + Module B 的实体属性数据。

**认知任务类型**：交叉推理。需要横跨多个实体的代码做交叉对比，推断实体间的交互规则和游戏的时间节奏。

**产出**：交互规则与系统演化文档。

**评估重点**：逻辑一致性——碰撞矩阵是否覆盖了 Module A 清单中所有实体组合？生成规则是否与配置表一致？预警信号是否与攻击代码对应？

---

## Module C: 交互与系统

基于 Module A 的实体 ID 和 Module B 的属性数据，推断实体间的交互规则和游戏系统演化规律。

### 碰撞层级矩阵

构建 Module A 清单中所有实体类型之间的碰撞关系矩阵。用实体 ID 引用。

| 实体 A | 实体 B | 碰撞关系 | 说明 |
|--------|--------|---------|------|
| 玩家子弹 | 敌人 | 碰撞+伤害 | 命中后子弹是否穿透下一个敌人 |
| 玩家子弹 | 地形-墙壁 | 碰撞+消失 | 墙壁阻挡子弹 |
| 玩家子弹 | 地形-水池 | 穿透 | 水池不阻挡子弹 |
| 敌人子弹 | 玩家 | 碰撞+伤害 | 命中后伤害值 |
| 敌人子弹 | 地形 | 按地形类型 | 需逐个地形类型判断 |
| 敌人 | 地形 | 按地形类型 | 阻挡 vs 穿透 |
| 玩家 | 地形 | 按地形类型 | 阻挡 vs 穿透 vs 减速 |
| 敌人 | 敌人 | 无碰撞/碰撞阻挡 | 是否敌人之间互相阻挡 |

矩阵必须覆盖 Module A 清单中所有实体类型的组合。对于每种具体地形类型（用 ID 引用），需单独判断其对不同子弹和实体的碰撞行为。

示例引用格式：`projectile_003` 穿过 `terrain_002`（水池），说明该弹幕不受水池阻挡。

### 波次与生成系统

| 字段 | 说明 |
|------|------|
| 波次结构 | 是否有明确波次划分，还是持续递增密度 |
| 波次间隔 | 两波之间的休息时间（秒） |
| 每波敌人配置 | 每波出现哪些敌人类型（用 ID）、数量比例 |
| 难度递增方式 | 数量增加/新类型引入/属性增强 |
| 精英/变异出现规则 | 出现频率和条件 |
| 生成位置 | 从屏幕边缘/随机位置/特定入口 |
| 生成节奏 | 一次涌入还是持续 trickle 流入 |

### 预警信号系统

| 字段 | 说明 | 为什么 bot 需要知道 |
|------|------|---------|
| 攻击预警动画 | Boss/精英攻击前的蓄力动画持续时间 | bot 预判闪避的机会窗口 |
| 地面预警标记 | AoE 攻击的地面红圈/阴影标记，出现到爆炸的时间 | bot 预判走位的机会窗口 |
| 音效信号 | 特殊攻击/精英出现/Boss 出场的独立音效 | bot 可通过音效检测威胁 |
| 状态视觉标识 | 精英发光/变大标识、自爆怪闪烁倒计时、Boss 阶段转换标识 | bot 通过视觉特征区分威胁等级 |

### 视野与信息边界

| 字段 | 说明 | 为什么 bot 需要知道 |
|------|------|---------|
| 屏幕可视范围 | 相机显示的游戏区域大小 | bot 的决策窗口就是屏幕范围 |
| 小地图 | 是否有小地图显示屏幕外敌人 | 无小地图则屏幕外威胁靠生成点预测 |
| 屏幕外危险指示 | 是否有方向指示器提示屏幕外威胁 | 影响站位决策——是否需要远离屏幕边缘 |
| UI 状态显示 | 当前波次/HP/冷却/敌人数量等 UI 内容 | bot 可通过 UI 获取哪些实时信息 |

### 升级选择策略

| 字段 | 说明 |
|------|------|
| 升级触发条件 | 击杀数量/经验累积/时间到达 |
| 选择池大小 | 每次升级提供几项选择 |
| 选择类型 | 新攻击技能/属性增强/防御提升/特殊效果 |
| 联动加成 | 某些选择是否有组合效果 |
| 升级频率 | 平均多久触发一次 |
| 推荐优先级 | 前期应选什么、后期应选什么 |

### 资源与冷却管理

| 字段 | 说明 | 为什么 bot 需要知道 |
|------|------|---------|
| 能量/魔力系统 | 技能是否消耗能量、恢复速度、上限 | 决定技能释放节奏 |
| 技能冷却体系 | 每个技能冷却时间、是否共享冷却 | 知道什么时候能用什么技能 |
| 连击/怒气系统 | 是否有连击计数影响伤害、怒气积累机制 | 影响攻击节奏决策 |
| 弹药限制 | 远程攻击是否有弹药上限、恢复方式 | 弹药有限时需要选择目标 |

### 评估重点

本模块的评估重点：**逻辑一致性**。

- 碰撞矩阵是否覆盖了 Module A 清单中所有实体类型的组合？是否有遗漏的碰撞关系？
- 每种具体地形的碰撞行为是否与 Module B 中该地形的属性一致（如 terrain_002 的穿透性）？
- 波次生成规则是否与配置表/代码中的实际生成逻辑一致？
- 每波敌人配置中引用的敌人 ID 是否都在 Module A 清单中存在？
- 预警信号是否与攻击代码中的实际预警机制对应？
- 视野范围是否与相机配置代码一致？
- 升级策略是否与 Module B 中的升级属性数据一致？
